# 校订答复

这里用于成稿后的校订。按本轮问题读回完整答复，检查判断是否有材料支持、已有成果是否接上、读者是否已得到所需解释或用法；缺的内容先补进正文，再处理表达。

## 从原文修改

局部修改取用户指向的原文或已确认版本，确定拟交付正文的替换范围，把改稿代回原段，按实际指代、因果和转场读一遍。按本轮已确认的详略和新段落的任务取舍：背景可以压缩，仍用于解释、论证或承接的事实与关系写进正文，并保留论述对象、必要条件和证据范围。需要重排时，把迁移处和承接处一起写好，作为用户可直接采用的句群交付。

尝试删去自我说明与制作备注，核对事实、解释、判断或用法是否有损。“原估计、标准误和P值予以保留”这类重复已知内容的备注直接删去；CI的来源、公式、分布与自由度保留。答复、图注和图内文字一并校订，空话直接删除。用户问改动时，直接交代具体改了什么。

需要独立重写时，给作者当前请求、这份原文、相关上下文与事实；旧失败稿留给选稿者比较。若争议在判断，先比较候选做法与证据，选定后再修文字。

## 自行检查或独立复核

按原问题的对象和尺度读回实际成品，核对结论、依据和用法。按每段给读者新增了什么判断、解释或用法取舍；重复结论保留在依据最完整处，概括和展开各有任务时保留。比较改进效果时，用相同请求和材料看两版实际输出，说明哪处改善、哪处相同、哪处丢了有用内容。原本已有的表现按原有成果交代。

先按原问题和相关原材料检查答复主体，找读者还缺哪些具体内容。总评、提醒或补充句群先留待后看，不靠它们替正文补判断；无待留句群时，核对主体即可，不另造总结。

再读完整稿及暂留内容，以用户实际取用的成品核对事实与证据条件；局部改稿连上下文一起读。涉及结果来源、验证独立性或比较口径的内容，放回相应结果旁；若补充改变主判断的强度、范围或必要总体判断，先修改主体，保留仍有作用的事实、机制或条件。只补答作者自行增加的问题则删去。需要他人核对时，给其原问、相关原文与完整成稿，请其按同一先后给具体意见，不继续委托；作者据原委托取舍并落实到正文，再读回。

一次预测核对示范：用户问这次参考谁，已核过事前快照与实际时间。可直接答：

> 这次参考清川：它在事件前保存的预测与实际一致；晨星是在事后更新页面。

“这次”已交代判断范围。后接“尚不足以说明长期准确率”没有改变本轮选择，删去。校订建议也按原问取舍。

来源：本技能的受控预测档案测试，站点为虚构，示范将证据范围并入当前判断。

## 应用局部替换

[局部替换脚本](../scripts/apply_edits.py) 可按唯一匹配的原文片段替换答复草稿，适合较长草稿或批量校订。

原稿文件：
```json
[{"id":"reply","draft":"原答复"}]
```
编辑文件：
```json
[{"id":"reply","edits":[{"before":"完整且唯一的原文","after":"替换文字"}]}]
```
删除时after为空字符串；无需改动可用空数组。用当前材料校订，事实核对由作者和复核者完成。

```text
python scripts/apply_edits.py --cases cases.json --edits edits.json --output revised.json
```

输入输出保存在当前任务可写位置。
